# clean nano kk（CN_AIIraiDaicho）ソース反映とロールバック手順

Power Apps の `clean nano kk` アプリのソースを、GitHub Actions から安全に反映し、必要なら元に戻すための手順です。2026-11-07 に、日報PDFのはみ出し対策（`S8_Nippo` の `<style>` の差し替え）で実施した内容を基にしています。

秘密の値（クライアントシークレット、API キー）は、この文書に書きません。

## 1. 対象と前提

| 項目 | 内容 |
|---|---|
| アプリの表示名 | `clean nano kk`（以前は `CN_AI依頼台帳`。名前が変わっています） |
| Solution | `CN_AIIraiDaicho` |
| 正本のソース | このリポジトリの `powerapps/CN_AI依頼台帳/Source` |
| 使う秘密 | GitHub の `POWER_PLATFORM_CLIENT_SECRET`（既存のバックアップと同じ） |
| 実行環境 | GitHub の `production` 環境 |
| 取り込みに使う PAC | 2.4.1（`pac canvas unpack` / `pack` は `--sources` と `--msapp` のみ対応） |

## 2. ワークフローの一覧

| ワークフロー | 役割 | 環境を変えるか |
|---|---|---|
| `cn-aiiraidaicho-backup-manual.yml` | Solution を書き出して保存する（バックアップ） | 変えない（読み取り専用） |
| `cn-aiiraidaicho-apply-s8-nippo-css.yml` | `S8_Nippo` の `<style>` を差し替えて取り込む | `apply` のときだけ変える |
| `cn-aiiraidaicho-rollback-from-backup.yml` | バックアップを取り込んで元に戻す | `apply` のときだけ変える |

`apply` が付くものは、どちらも、既定は確認のみ（`dry-run`）です。取り込みには、承認の文言の入力が必要です。

## 3. 反映の手順

1. **バックアップを取る。** `cn-aiiraidaicho-backup-manual.yml` を実行します。成功すると、成果物 `CN_AIIraiDaicho-unmanaged-backup` が、30日間保存されます。実行の ID を控えます。
2. **確認のみ（dry-run）を実行する。** `cn-aiiraidaicho-apply-s8-nippo-css.yml` を `mode=dry-run` で実行します。
3. **ログで次を確認する。**
   - 差し替えの前に、`Src/S8_Nippo.fx.yaml` と `Other/Src/S8_Nippo.pa.yaml` の両方で、変更前の `<style>` が、ちょうど1か所ずつ見つかっている（`old=1`）。
   - 組み立て後に、変わったソースの yaml が、この2ファイルだけで、各ファイルの差分が、ちょうど1行（`-1 +1`）である。
   - 他の画面のソースが変わっていない。
   - `Entropy/checksum.json` が変わるのは、想定どおりです（ソースを編集した記録）。`PA2001` の警告も、同じ理由で無視できます。
4. **人間が承認する。** 上の確認が、すべて通ったことを見て、取り込みを承認します。
5. **取り込む。** `mode=apply`、`approval=APPLY-S8-NIPPO-CSS` で実行します。取り込み後に、環境から書き出し直し、新しい `<style>` が、ちょうど1か所あることを、自動で確認します。
6. **実機で確認する。** アプリで、日報を1件選んで「PDFを確認」を押し、PDF を見ます。

### 別の変更を反映したい場合
`cn-aiiraidaicho-apply-s8-nippo-css.yml` の、変更前と変更後の文字列（`OLD`、`NEW`）と、取り込み後の確認に使う目印の文字列を、書き換えます。次の保護は、そのまま残してください。

- Solution 名、アプリが1つだけ、表示名の確認
- 変更前の文字列が、ちょうど1か所のときだけ差し替える
- 組み立て後に、変わったソースが、想定のファイルだけで、差分が想定の行数であることを確認する

## 4. ロールバックの手順

バックアップを取り込んで、反映前の状態に戻します。

> **注意**: Solution 全体が、バックアップを取った時点の状態に戻ります。バックアップより後に加えた、他の変更（他の画面の編集など）は、失われます。使う前に、必ず人間が判断してください。

1. `cn-aiiraidaicho-rollback-from-backup.yml` を `mode=dry-run` で実行します。`backup_run_id` には、バックアップの実行の ID を入れます。
2. ログで、次を確認します。
   - チェックサムが一致している（`checksum match: True`）。
   - バックアップの `S8_Nippo` に、元の `<style>` が、ちょうど1か所あり、新しい `<style>` がない（`old style=1 new style=0`）。
3. 人間が承認したら、`mode=apply`、`approval=ROLLBACK-S8-NIPPO-CSS` で実行します。取り込み後に、元の `<style>` が戻ったことを、自動で確認します。

バックアップの成果物は、30日で期限が切れます。

## 6. つまずいた点と対処（今後の注意）

| 事象 | 原因 | 対処 |
|---|---|---|
| バックアップが、表示名の確認で停止した | アプリの表示名が `clean nano kk` に変わっていた | 確認基準を新しい名前に更新。書き出しの保存を、確認より前に移した |
| `pac: command not found` | インストールした `pac` が、コマンド名では呼べなかった | `PACPATH` 配下から実行ファイルを探して呼ぶ |
| `pac canvas unpack` が使用法を表示して停止 | PAC 2.4.1 は `--layout` / `--overwrite` に非対応 | `--sources` と `--msapp` だけを使う |
| `S8_Nippo` のソースが2か所あり、確認が停止 | 展開結果に、`.fx.yaml` と、アプリ内部の `.pa.yaml` の両方がある | 2か所を同時に差し替え、各ファイルの一致数を確認する |
| 本番確認が、デプロイ直後に失敗した | 再デプロイ中の最初の通信が、時間切れになった | デプロイの完了を待って実行する。`/health` の通信失敗のみ再試行する |

## 7. 守ること

- 取り込みは、人間の明示的な承認を得てから行います。承認の文言は、人間の承認を得たあとにだけ入力します（承認がない状態で、自動的に入力してはいけません）。
- 既存のアプリ、Solution を、削除、改名しません。
- 秘密の値を、ログや文書に出しません。
- 取り込みの前に、必ずバックアップを取り、確認のみの動作で結果を読みます。
- Studio で、誰かが同じアプリを編集中のときは、取り込みで上書きされる恐れがあります。実行前に確認してください。
- GitHub の正本を更新しただけでは、実アプリへの反映は完了していません。取り込み後に、環境を書き出し直して確認し、実機でも確認してください。
