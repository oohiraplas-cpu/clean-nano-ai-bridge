# 新規社員登録フロー 作成手順（Power Automate の画面操作）

状態: 手順書（BUILD GUIDE）。実環境には何も作成していない。設計は `new-employee-registration-flow.md` を参照。
作業は PC のブラウザで行う（スマホの Power Automate アプリではフローを作れない）。

## 前提と初期値（変更したい場合は言ってください）

| 項目 | 初期値 | 理由 |
|---|---|---|
| 承認者 | オーナー 1 人 | 決定済み |
| 社員ID | 承認者が承認時に入力 | フォームに質問がない |
| 所属・入社日 | 承認者が承認時に入力 | フォームに質問がない |
| 希望職種 | 台帳に入れない | 対応する列がない |
| 対象 | 登録区分が「社員」「アルバイト」のみ | 協力会社の行き先が未確認 |
| 機微情報（住所・生年月日・保険番号・電話・緊急連絡先） | リストにも通知にも出さない | 設計書の追補5 |
| 承認の期限 | 7 日。期限切れは登録せず記録して通知 | 未決定のため仮置き |

## 先にやること（フォーム所有者）
1. Forms の共有設定を「特定のユーザー」に変更する。
2. Forms のプライバシーに関する声明を追加する。

## フローの作り方
1. Power Automate →「作成」→「自動化したクラウド フロー」。名前: `CN_新規登録_社員・アルバイト`。トリガー: Forms「新しい応答が送信されるとき」。対象のフォームを選ぶ。
2. 「応答の詳細を取得する」（同じフォーム、応答ID＝トリガーの応答ID）。
3. **条件: 登録区分が「協力会社」なら終了**（今回の範囲外）。終了前に仮登録台帳へ「対象外」と記録するかは任意。
4. **検証**: 氏名・フリガナ・メール・電話・住所が空でないこと。不正なら「終了（失敗）」。台帳には書かない。
5. **二重処理の防止**: SharePoint「複数の項目の取得」（`CN_入社申請_仮登録台帳`、フィルター `FormsResponseId eq '<応答ID>'`）。1 件以上あれば終了。
6. **仮登録の記録**: SharePoint「項目の作成」（`CN_入社申請_仮登録台帳`）。
   - `Title`: 「新規登録申請」＋申請日（**氏名は入れない**）
   - `FormsResponseId`: 応答ID
   - `ApplicantCategory`: 登録区分
   - `SubmittedAt`: 申請日時（ISO 8601 の文字列。列がテキスト型のため書式を固定する）
   - `ApprovalStatus`: 承認待ち
   - `RegistrationStatus`: 未登録
7. **承認**: Teams「アダプティブ カードを投稿して応答を待つ」（宛先: 承認者 1 人）。カードの表示は、氏名・登録区分・申請日のみ（機微情報は出さない）。入力欄: 社員ID、所属、入社日、承認 / 却下。タイムアウト 7 日。
8. **条件: 承認か**
   - 却下・期限切れ: 仮登録台帳を `ApprovalStatus` = 却下 / 期限切れ に更新して終了。
   - 承認: `ApprovalStatus` = 承認、`ApproverUPN`（承認者の応答から取得）、`ApprovedAt` を更新。
9. **重複確認**: `CN_社員台帳` を `EmployeeID eq '<入力された社員ID>'` で取得。1 件以上あれば登録せず、`RegistrationStatus` = 重複 に更新して通知。
10. **正式登録**: SharePoint「項目の作成」（`CN_社員台帳`）。
    - `Title` = 氏名、`EmployeeID` = 入力された社員ID、`Department` = 入力された所属、`HireDate` = 入力された入社日、`EmployeeCategory` = 登録区分、`EmploymentStatus` = 在職（※選択肢の文言を台帳で確認）
    - `EntraObjectId` は**書かない**（アカウント発行後の別工程）。
11. **結果の記録**: 仮登録台帳の `RegistrationTargetId` = 作成された項目ID、`RegistrationStatus` = 登録済み。
12. **失敗時**: 手順 10 が失敗したら、`RegistrationStatus` = 失敗 に更新し、承認者へ通知（通知文にエラーの詳細や個人情報を入れない）。「実行後の構成」で、手順 10 の失敗時に 12 を実行するよう設定する。
13. **通知**: 承認者へ「登録完了」（項目IDのみ）。

## 実環境で確認すること
- `Department` / `EmploymentStatus` / `EmployeeCategory` の**選択肢の文言**（SharePoint のリスト設定で確認。画面で見えた例: 在職、一般社員、内勤）。
- Teams のアダプティブ カード（応答待ち）が、あなたのテナントで追加費用なしで使えること。
- 社員IDの採番ルール（既存の形式の例: `E019`）。

## 動作確認（テスト用の応答で）
1. 社員の応答を 1 件送る → 仮登録台帳に 1 行 → カードに承認 → `CN_社員台帳` に 1 行、台帳の `RegistrationTargetId` に項目ID。
2. 同じ応答 ID が再処理されないこと。
3. 同じ社員 ID で再登録 → 登録されないこと。
4. 却下・期限切れ → `CN_社員台帳` に書かれないこと。
5. 協力会社の応答 → `CN_社員台帳` に書かれないこと。
6. 台帳・通知・実行履歴に、機微情報が出ていないこと。
7. テスト用の行は、確認後に無効を示して残す（削除しない）。

## ロールバック
フローをオフにする。登録済みの行は削除せず、`EmploymentStatus` または `Remarks` で無効を示す。
